PassWall 企业级配置与网络深度调优实战手册

设备: Newifi 3 (D2) MT7621 固件: ImmortalWrt 23.05.4 插件: PassWall (Trojan-Plus / Xray) 联动: 铁威马 NAS (0.49ms / 19ms) 验证: 2026-10-31 全量通过

一、 架构迭代背景：为何弃用 v2rayA 切换至 PassWall？

在此前的使用中，Newifi 3 曾运行 OpenWrt 25.12.5 快照版与 v2rayA。但随着网络设备与服务增多，遭遇了多重底层瓶颈：

对比维度 v2rayA 架构痛点 ImmortalWrt 23.05.4 + PassWall 方案
系统稳定性 25.12.5 快照版在 MT7621 MIPS 架构下 Go 符号表偶发越界，报错 panic before malloc heap initialized 官方成熟稳定版（23.05.4），内核 5.15 驱动成熟，零内存越界崩溃
内存与负载 常驻内存高，启停时无法彻底回收，内存余量常低于 50MB 纯 C / 紧凑 Go 架构，系统空闲内存高达 320MB+，CPU 负载长期仅 0.2~0.3
节点协议兼容 捆绑的新版 Xray 删除了 allowInsecure: true，导致伪装 SNI 的 Trojan 节点证书握手失败 原生支持 Trojan-Plus 与 Xray 双引擎，100% 兼容各类中转机场节点
透明代理与分流 独立于系统防火墙，容易截胡局域网内部通信，配置复杂且易与终端客户端冲突 基于 nftables / iptables 底层链式分流，支持端口级、IP 级无损旁路放行

二、 PassWall 安装与核心组件部署

  1. 软件源更新与安装
    进入路由器后台 系统 -> 软件包，点击 更新列表...，搜索并安装：
    luci-app-passwall 与 luci-i18n-passwall-zh-cn。
    安装完成后刷新后台，顶部导航栏即出现 服务 -> PassWall 菜单。
  2. 节点导入与密码丢失排障（关键避坑）
    部分机场订阅转换脚本在导入特定 Trojan 节点时，密码字段（UUID）在前端提交时变空，导致 PassWall 无法启动：
    # 1. SSH 登录路由器，查找节点 ID
uci show passwall | grep -iE '美国|US'

# 2. 补全对应节点的密码字段并生效
uci set passwall.<节点ID>.password='你的节点密码或UUID'
uci commit passwall
/etc/init.d/passwall restart

三、 整网打通：NAS 与 Tailscale 打洞深度调优

⚠️ 代理插件导致 Tailscale 变卡的根因剖析

PassWall 默认接管所有 UDP 流量（1:65535）。Tailscale 发送的 STUN 打洞探测包（端口 3478）和通信包（端口 41641）被路由器代理抓包并转发至海外服务器，导致两端无法完成 NAT 穿透握手，被迫降级为延迟高达 1500ms+ 的香港中继 DERP(hkg)！

核心调优三部曲：

  1. PassWall 放行 Tailscale 通信端口
    在 PassWall 转发设置中将 STUN 与 Tailscale 端口加入非代理列表：
    uci set passwall.@global_forwarding[0].udp_no_redir_ports='3478,41641'
uci commit passwall
/etc/init.d/passwall restart
    验证生效：nft list table inet passwall | grep 41641 会输出 udp dport { 3478, 41641 } counter return，证明打洞数据直接放行，不再进代理。
  2. 防火墙配置静态端口转发 (DNAT)
    外部打洞连接需要能穿透路由器直接抵达 NAS：
    uci add firewall redirect
uci set firewall.@redirect[-1].name='tailscale'
uci set firewall.@redirect[-1].src='wan'
uci set firewall.@redirect[-1].proto='udp'
uci set firewall.@redirect[-1].src_dport='41641'
uci set firewall.@redirect[-1].dest_ip='192.168.1.198'
uci set firewall.@redirect[-1].dest_port='41641'
uci set firewall.@redirect[-1].target='DNAT'
uci commit firewall
/etc/init.d/firewall restart
  3. 启用 Full Cone NAT（全锥型 NAT）
    在防火墙配置中确保开启全锥型 NAT 加速：
    uci set firewall.@defaults[0].fullcone='1'
uci commit firewall
    在终端运行 tailscale netcheck，输出 MappingVariesByDestIP: false，代表路由器已工作在全锥型独立映射模式，为打洞提供最高成功率。

四、 铁威马 NAS 局域网与远程两套 IP 访问法则

使用场景 访问入口 网络协议 实测延迟 实际传输速率 适用业务
公司办公室内 smb://192.168.1.198 局域网物理直连 0.4ms ~ 0.8ms 110MB/s ~ 280MB/s (千兆跑满) 大文件剪辑、备份、工程协同
居家 / 异地出差 smb://100.87.114.20 Tailscale P2P 穿透 19ms ~ 35ms 跑满办公室宽带上行上限 远程资料调取、代码同步
🚨 避坑警示

人在办公室时，切勿通过 100.87.114.20 挂载硬盘！否则会触发路由器 NAT 回环（Hairpinning），导致本可在内网传输的流量绕道外网，不仅增加路由器负荷，还会导致速度骤降。

五、 Wi-Fi 5G 芯片硬件防崩溃加固

💥 硬件崩溃日志还原

Newifi 3 的 5G 无线芯片为联发科 MT76x2E。当 5G 工作在低频 36 信道且开启了弱信号剔除时，路由器内核日志（dmesg）会不断报错并掉线：
[103539.761045] ieee80211 phy1: Hardware restart was requested

终极加固命令：

# 1. 锁死中国国家代码
uci set wireless.radio0.country='CN'
uci set wireless.radio1.country='CN'

# 2. 5G 切换到高频纯净信道 149 (5.745 GHz)
uci set wireless.radio1.channel='149'

# 3. 关闭弱信号丢包踢除机制（避免移动设备跳频掉线）
uci set wireless.default_radio0.disassoc_low_ack='0'
uci set wireless.default_radio1.disassoc_low_ack='0'

# 4. 提交配置并重载 Wi-Fi 驱动
uci commit wireless
wifi reload

六、 域名分流与 AI 业务规则设计

1. 节点分配原则

TCP 主节点优先选用 [IPLC·US] 美国 专线。物理延迟稳定（~140ms），出口 IP 纯净，100% 兼容 OpenAI / ChatGPT、Google Gemini / AI Studio、Anthropic / Claude、Cursor (含 WorkOS 鉴权及 x.ai 探针)。

2. DNS 防污染与国内秒开

通过 ChinaDNS-NG + Dnsmasq 深度防污染方案，国内域名直连 223.5.5.5，海外域名走安全远程 DNS（1.1.1.1），同时 chnroute 大陆 IP 集合在内核层 0 毫秒放行，彻底消除冷启动握手超时。
