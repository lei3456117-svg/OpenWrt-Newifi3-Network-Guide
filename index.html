一、 核心概念与避坑必读（核心实战经验总结）

1. 为什么误卸载 dnsmasq 导致路由器瘫痪？

事故还原：
在早期尝试安装代理插件时，过程中把系统的 dnsmasq 删除了。
技术内幕：
在 OpenWrt 中，dnsmasq 同时身兼两职：DHCP 服务器（向局域网手机/电脑分发 IP） 和 DNS 缓存代理（把域名解析为 IP）。一旦直接卸载它，局域网内的设备会立刻分配不到 IP（电脑提示 169.254.x.x 自分配私有地址），路由器自身也立刻丧失域名解析能力，导致后续从官方源下载安装 dnsmasq-full 的请求无法解析软件源域名，陷入“进不去后台也装不上软件”的死锁状态。

2. dnsmasq-full 与精简版 dnsmasq 的本质差异

很多人以为完整版只是多了一点周边工具，实际上它是科学上网与规避 DNS 投毒的绝对核心生命线：

功能对比项系统自带精简版 dnsmasq全功能版 dnsmasq-full对 AI / 科学上网的决定性影响
安装体积 ~180 KB ~380 KB 仅相差 200 KB，但内核编译参数截然不同
基础 DHCP 与解析 支持 支持 分配 192.168.1.x IP，普通国内网站解析
IPSet / NFTables 动态集合 ❌ 彻底阉割 完整支持 分流命脉：将解析出来的真实海外 IP 动态注入防火墙名单交给代理核心，精简版不支持会导致分流彻底失效
DNSSEC (DNS安全扩展) ❌ 彻底阉割 完整支持 防投毒核心：校验上级 DNS 返回签名的真实性，彻底屏蔽运营商的假 IP 伪造
高级分流与自定转发通道 ❌ 彻底阉割 完整支持 配合 v2rayA / Xray 实现 DoH 加密解析与国内/海外流量精准拆分
为什么配置完成后，便宜订阅也能稳定连接 Anti-gravity / Gemini？
原先连接失败，很多时候不是因为节点便宜，而是因为国内网络环境对 alkalimakersuite-pa.clients6.google.com（Anti-gravity 核心接口）进行了 DNS 域名投毒，精简版把假 IP 当真地址交给了电脑，导致通信直接中断。
当正确安装了 dnsmasq-full 并开启了 “防 DNS 污染协议” 后，路由器将 AI 域名的解析通过加密通道直接向海外官方发起请求，拿到了真实无污染的机房 IP。只要海外 IP 是真实的，哪怕几块钱的便宜美国节点也能瞬间秒开！

📌 实测验证（关键环境说明）：
在调试 NAS 时，Mac 电脑是通过网线直接接入路由器 LAN 口的（完全不经过交换机），且 Mac 本地的 Clash + Antify 完全处于关闭退出状态。此时 Mac 作为一个纯粹的普通局域网客户端，所有外网访问 100% 依赖路由器上的 v2rayA 透明代理与分流规则，实测 Anti-gravity 与 Gemini 极速顺畅响应。这彻底验证了：只要 DNS 干净且分流规则正确，单靠硬路由搭载廉价节点也能稳定支撑高要求 AI 生产力！

3. 为什么硬路由做旁路规则会导致 YouTube 4K 转圈（双重代理套娃）？

问题现象：
把 Mac 插在路由器 LAN 口，试图让 Mac 走本地的 Clash/Antify（昂贵美国节点），而路由器走 v2rayA（便宜节点），即使在路由器后台给 Mac 加上直连放行规则，访问 YouTube 依然严重卡顿，甚至 0 B/s。
底层根因：
v2rayA 开启透明代理（TProxy）后，是在 Netfilter 底层拦截端口 53 和所有非大陆流量。Mac 本地的 Antify 已经对数据包进行了一次封装，路由器接收到这个加密包后，由于不知道里面是什么，根据外部目标服务器又强行套上了一层 v2rayA 的代理，形成了 “代理包着代理”的双重代理套娃。双重握手产生巨大的延迟和近乎 100% 的丢包。
终极解法：
硬件物理隔离：把桌面交换机放在最前置，Mac 电脑直连交换机（纯净直出公司网），路由器 WAN 口插交换机（专职提供无线翻墙）。

二、 从零到一全流程实操部署记录

步骤 1：Breed 引导模式与固件重刷

  1. 路由器完全断电，使用卡针或牙签顶住 Newifi 3 背后的 RESET 小孔保持按住不放。
  2. 插入电源，观察路由器前面板指示灯。当指示灯开始交替闪烁/快速双闪时，松开 RESET 键。
  3. 网线连接电脑与路由器 LAN 口，此时路由器没有运行 DHCP，需手动配置 Mac 网卡：
    • 打开 Mac【系统设置】->【网络】->【以太网】->【TCP/IP】；
    • 配置 IPv4 改为 手动：IP 地址 192.168.1.2，子网掩码 255.255.255.0，网关 192.168.1.1。
  4. 浏览器无痕窗口打开 http://192.168.1.1，进入 Breed Web 恢复控制台。
  5. 点击【固件更新】，上传下载好的官方纯净原版：openwrt-25.12.5-ramips-mt7621-d-team_newifi-d2-squashfs-sysupgrade.bin (7.4MB) 刷入。
  6. 刷入等待 2 分钟，将 Mac 网卡 IPv4 改回 “使用 DHCP”。

步骤 2：企业局域网环境适配（MAC 地址与 WAN 静态绑定）

公司网络采用交换机端口与 MAC 白名单绑定机制，为了防止路由器抢占 Mac 电脑的身份，两台设备必须分别设置：

接入设备物理硬件 MAC 地址分配 IPv4 地址网关 / 掩码 / DNS
Mac 电脑 6C:1F:F7:CD:18:52 (原机网卡) 172.16.122.57 (DHCP 自动分配) 172.16.122.254 / 255.255.255.0
Newifi 3 路由器 20:76:93:4A:E3:08 (出厂原生物理 MAC) 172.16.122.55 (静态绑定保留) 172.16.122.254 / 255.255.255.0
DNS: 221.6.4.66, 114.114.114.114		 
# SSH 登录路由器写入 WAN 口网络配置 (/etc/config/network)
uci set network.wan.proto='static'
uci set network.wan.ipaddr='172.16.122.55'
uci set network.wan.netmask='255.255.255.0'
uci set network.wan.gateway='172.16.122.254'
uci set network.wan.dns='221.6.4.66 114.114.114.114'
uci set network.wan.macaddr='20:76:93:4a:e3:08'
uci commit network
/sbin/ifup wan

步骤 3：U 盘 Extroot 格式化与系统盘 3.5GB 扩容

Newifi 3 仅剩 23MB Flash，安装 xray 核心与规则库需要近 100MB 空间，必须做外置存储扩容：

# 1. 安装磁盘驱动与分区格式化工具
apk update
apk add kmod-usb-storage kmod-fs-ext4 block-mount e2fsprogs fdisk

# 2. 确认 U 盘设备号（/dev/sda1），将其格式化为 Linux ext4
mkfs.ext4 -F /dev/sda1

# 3. 将现有的 /overlay 系统文件完整同步复制进 U 盘
mkdir -p /mnt/sda1
mount /dev/sda1 /mnt/sda1
cp -a -f /overlay/. /mnt/sda1/
umount /mnt/sda1

# 4. 配置系统开机自动把 U 盘挂载为系统根盘 /overlay
uci set fstab.overlay='mount'
uci set fstab.overlay.device='/dev/sda1'
uci set fstab.overlay.target='/overlay'
uci set fstab.overlay.enabled='1'
uci commit fstab
/etc/init.d/fstab enable

# 5. 重启生效
reboot

重启后通过 df -h /overlay 检查，根分区可用容量成功变为 3.2 GB。

步骤 4：核心组件与完整汉化包安装

# 1. 软件源列表更新
apk update

# 2. 无缝平替安装全功能 dnsmasq-full
apk del dnsmasq
apk add dnsmasq-full

# 3. 安装 v2rayA 及底层 xray 核心
apk add v2raya xray-core luci-app-v2raya luci-i18n-v2raya-zh-cn

# 4. 安装大陆分流规则数据库
apk add v2ray-geoip v2ray-geosite

# 5. 安装网页终端 TTYD 及全模块简体中文语言包
apk add ttyd luci-app-ttyd luci-i18n-ttyd-zh-cn
apk add luci-i18n-base-zh-cn luci-i18n-firewall-zh-cn luci-i18n-package-manager-zh-cn luci-i18n-attendedsysupgrade-zh-cn

# 6. 启动并启用开机自启
/etc/init.d/v2raya enable && /etc/init.d/v2raya start
/etc/init.d/ttyd enable && /etc/init.d/ttyd start
/etc/init.d/uhttpd restart

步骤 5：v2rayA 科学上网与 AI 多出口精准分流配置

  1. 浏览器进入后台：http://192.168.1.1:2017（首次进入设置用户名密码）。
  2. 导入节点：点击右上角【导入】，推荐复制机场提供的 Shadowrocket（小火箭）订阅链接 粘贴拉取。
  3. 多出口创建：
    • 左上角在【正在运行】旁边，点击药丸标签旁边的设置，选择 【新增一个出口】，命名为：OpenAi；
    • 在 OpenAi 出口绑定的节点下拉菜单中，选择你订阅里的 美国节点；
    • 默认的 PROXY 出口绑定你日常使用的便宜香港/亚太节点。
  4. 全局参数调整：点击右上角【设置】：
    • 透明代理/系统代理：启用：大陆白名单模式
    • 透明代理实现方式：tproxy
    • 开启IP转发 / 开启端口分享：两个黄色高亮开关均开启
    • 防止DNS污染：使用已配置的DNS协议防止DNS污染
  5. 自定义规则 RoutingA：滚到底部在规则框中写入以下分流规则： 
    default: proxy
# write your own rules below
domain(openai.com)->OpenAi
domain(chatgpt.com)->OpenAi
domain(auth0.openai.com)->OpenAi
domain(gemini.google.com)->OpenAi
domain(generativelanguage.googleapis.com)->OpenAi
domain(aistudio.google.com)->OpenAi
domain(alkalimakersuite-pa.clients6.google.com)->OpenAi
domain(domain:mail.qq.com)->direct

domain(geosite:google-scholar)->proxy
domain(geosite:category-scholar-!cn, geosite:category-scholar-cn)->direct
domain(geosite:geolocation-!cn, geosite:google)->proxy
domain(geosite:cn)->direct
ip(geoip:hk,geoip:mo)->proxy
ip(geoip:private, geoip:cn)->direct
  6. 点击【保存并应用】，主界面勾选节点点击左上角【启动】。
